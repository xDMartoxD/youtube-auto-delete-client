# Architecture

PlaylistMaster's frontend: clean up, merge and create playlists on YouTube,
YouTube Music, Spotify, Apple Music and Amazon Music. Spotify, Apple Music and
Amazon Music are served by mock providers in the backend (demo data); the UI
marks them with a "Demo" badge.

## Layers

```text
components/   UI. Reads state and triggers actions only through hooks.
   ↓
hooks/        Public interface to state (useProviders, usePlaylists, ...) and
              pure UI logic (useTrackSelection: filters + multi-select).
   ↓
stores/       Zustand stores holding server state (providers, playlists,
              cached tracks) and the async actions that change it.
   ↓
services/     Thin wrappers over the generated SDK. Never throw: they return
              ServiceResult<T, E> via toServiceResult().
   ↓
api/          Generated by `yarn generate:api` from ../backend/openapi.json.
              Do not edit by hand.
```

Rules:

- Components never import from `stores/` or `api/` functions directly
  (importing generated *types* from `@/api` is fine).
- UI-only state (selection, filters, form fields) lives in components/hooks,
  not in stores.
- Stores expose atomic selectors so components re-render only for the slice
  they read.

## Main screens

`pages/landing` renders `SignInHero` when signed out and `Workspace` when
signed in. The workspace has a provider switcher and three tools:

| Tool | Component | Backend endpoint |
| --- | --- | --- |
| Clean up | `components/cleanup/cleanup-view.tsx` | `POST /v1/providers/{p}/playlists/{id}/tracks/remove` |
| Merge | `components/merge/merge-view.tsx` | `POST /v1/providers/{p}/playlists/merge` |
| Create | `components/create/create-view.tsx` | `POST /v1/providers/{p}/playlists` |

Provider brand colors and names used before sign-in live in
`constants/providers.ts`.

## Errors

API errors have the shape `{ detail, user_message }`. `utils/error-handler.ts`
shows `user_message` in a toast; stores call `handleServiceError` after every
service call.
